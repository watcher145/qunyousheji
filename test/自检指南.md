# 群友设计扩展 · 技能自检与语义检索指南

> **给 AI 模型的使用说明**：本文档是"无名杀群友设计"扩展的**技能开发标准流程**。
> 任何新会话/新模型接手技能开发任务时，先读完本文档，再按"标准流程"执行。

## 一、这套机制是什么

两个独立工具，解决技能开发的两个痛点：

| 工具 | 解决什么 | 何时用 |
|---|---|---|
| **语义检索器** `skill-search.mjs` | 拿到技能描述，不知道"该抄哪个原生技能/用什么模板" | **写技能前**必跑 |
| **自检测试** `skill-test.mjs` | 写完技能，不知道"有没有写错（事件名错/subSkill没挂/ReferenceError）" | **写完后**必跑 |

## 三、标准流程（写任何技能）

### 第 1 步：语义检索（写之前，30 秒）

```bash
node "G:\game\noname\resources\app\extension\群友设计\test\skill-search.mjs" "完整的技能描述文本"
```

输出 Top 5 参考技能（含 描述/时机/类型/API/标签），例如：

```
[1] scstaoluan (滔乱)  综合0.72 语义0.723
    描述: 出牌阶段限一次。你可以将一张牌当任意一种基本牌或普通锦囊牌使用。
    标签: viewAs
```

**用法**：
- 检索结果直接作为**代码参考**——查看 Top 技能在 `character/` 里的完整实现，复制其结构（trigger 事件名、viewAs 写法、chooseButton 结构等）
- 结合 `.opencode/skills/技能开发模式/技能描述语义映射表.md`（术语→实现规则）使用
- 语义相似度 >0.7 的通常是强相关；<0.3 会提示"置信度低"，此时手动评估或问设计者

### 第 2 步：写代码 + 翻译

按 `.opencode/skills/技能开发模式/SKILL.md` 模板库写，遵守 AGENTS.md 全部约定。

### 第 3 步：自检（写完后，30 秒）

```bash
node "G:\game\noname\resources\app\extension\群友设计\test\skill-test.mjs"
```

**目标：总检查 N 项，失败 0 项**。有 FAIL 则修复后重跑。

## 四、自检 FAIL 解读表（重点）

| FAIL 类型 | 含义 | 是不是真 bug | 修复方法 |
|---|---|---|---|
| `content 执行: ReferenceError: xxx is not defined` | content 引用未定义变量 | ✅ 必真 | 见下表 |
| `content 全局化: ReferenceError` | content 引用模块函数（StepCompiler 全局作用域不可见） | ✅ 必真 | 挂到 `lib.skill.技能id.方法`，content 用 `lib.skill.xxx.yyy()` 调用 |
| `子技能 xx 未被 group 挂载也未动态引用` | subSkill 不自动挂载 | ✅ 必真（除非是标记/backup） | 主技能加 `group: ["技能id_子技能"]`，或 content 里 `addSkill/addTempSkill` 动态挂 |
| `事件名 xx 引擎与扩展均无此事件` | trigger 写了不存在的时机 | ✅ 必真 | 查 TRIGGER_REFERENCE.md 改正确事件名 |
| `翻译 xx 缺少技能名与 info 翻译` | 玩家可见技能无翻译 | ✅ 必真 | translate/skill.js 补 `xx: "名"` + `xx_info: "描述"` |
| `角色 xx 技能 yy 不存在` | 角色挂了未定义的技能 | ✅ 必真 | 补技能定义或改角色技能列表 |
| `翻译 xx 缺少`（纯 mod 辅助） | mod-only 无 UI 技能 | ❌ 误报 | 忽略（测试已放行纯 mod） |
| `content 执行: [mock限制]` | mock 假引擎不支持某 API | ❌ 误报 | 忽略（前缀 [mock限制]） |
| `content 执行: TypeError: xx is not a function`（无 [mock限制] 前缀） | content 调了不存在的 API | ✅ 必真 | 查 player.js/get 确认正确方法名 |

### ReferenceError 常见三类（重点）

1. **`content()` 无参**：content 函数没写参数 `(event, trigger, player)` 但体内用了这些变量
   ```js
   // ❌ 错
   content() { delete player.storage.xxx; },
   // ✅ 对
   content(event, trigger, player) { delete player.storage.xxx; },
   ```
2. **content 引用模块函数**：content 被 StepCompiler 编译到全局作用域，模块 import 的函数不可见
   ```js
   // ❌ 错：qunyou_xxx_helper 是模块 import 的
   content(event, trigger, player) { qunyou_xxx_helper(player); },
   // ✅ 对：挂到技能对象，content 经 lib 访问
   // 技能定义处加：helper(player) { return qunyou_xxx_helper(player); },
   content(event, trigger, player) { lib.skill.本技能id.helper(player); },
   ```
3. **content 引用未导出的模块常量/变量**
   ```js
   // ❌ 错：const MY_LIST = [...] 在模块顶层，content 里直接用
   while (used.length < MY_LIST.length) {...}
   // ✅ 对：挂到技能对象
   // 技能定义处加：names: MY_LIST,
   while (used.length < lib.skill.本技能id.names.length) {...}
   ```

node "G:\game\noname\resources\app\extension\群友设计\test\eval-search.mjs"

## 六、其他约束（务必遵守）

1. **不要改**：`mock-noname.mjs`、`loader.mjs`、`engine-events.mjs`、`engine-apis.mjs`、`skills-corpus.json`、`embed-cache.json`、`models/`——它们是自检/检索的依赖
2. **跑自检**是每个技能完成的必要条件，FAIL 0 才算完成；修完所有 FAIL 后报告给用户
3. 检索结果只是参考，**最终以技能描述 + 设计者确认为准**；检索不到时（置信度低）主动问设计者
4. 技能代码写在 `src/skill/*.js`（qunsai/sanshe/yachai/clan），翻译在 `src/translate/skill.js`，角色在 `src/character/*.js`，包分配在 `src/package.js`
